# EduConnect — Independent Architectural Assessment

**Repo:** `/Volumes/Samsung T7 1TB/Educonnect/Clone GitHub Educonnect/school-app` (§ `main` @ `838b5b2`, read-only assessment, 2026-11-11)
**Companion docs:** `ARCH-02_SYSTEM_DIAGRAMS.md` · `ARCH-03_DEPENDENCY_ANALYSIS.md` · `ARCH-04_ARCHITECTURAL_RISKS.md` · `ARCH-05_IMPROVEMENT_ROADMAP.md` · `00-04` (security reconciliation, same session)
**Method:** full-tree inventory via 3 parallel read-only explorations + first-hand line reads of all kernel files. ~9,500 lines of backend `src/` + migrations, full Next.js frontend surface, manifests, CI/deploy scripts examined.

Each area below: **(a)** existing implementation, **(b)** concrete evidence, **(c)** consequences, **(d)** defect vs ordinary debt, **(e)** smallest reasonable improvement with effort/dependencies. No microservices or heavy infrastructure are recommended; sizing is for a small team.

## 1. Overall Architecture & Domain Boundaries

**(a) Implementation.** Single-repo npm-workspaces monorepo (root `package.json` `workspaces: ["frontend","backend"]`) with one committed `bun.lock` (lockfileVersion 2). Backend = Express 4.22.3 + Socket.IO 4 on a single Node process; database = one better-sqlite3 file through knex + `pg` dialect opt-in. Frontend = Next.js 15 App Router used as a *fully client-rendered SPA* (44 of ≈50 route files begin `'use client'`), statically exported (`frontend/out/`, 11 MB) and consumed by a Capacitor 8 Android shell (`frontend/android/`, `capacitor.config.ts` → `webDir: 'out'`) and by plain browsers via `npm run dev`. Semantic domains are split into 23 `*routes.js` modules (academics, announcements, assignments, attendance, auth, classes, courses, discipline, feedback, finance, gradebook, messages, notifications, quizzes, schedules, school, study-planner, tickets, upload, videos, analytics, AI). Globally shared utilities (`db`, auth helpers, cache, SMS, audit) live outside modules — a classic layered monolith.

**(b) Evidence.** Root manifests (1–52, backend 1–39, frontend 1–30); middleware pipeline order (`app.js` 55–121); embed-local per-domain mounts (`app.js:445–467`); module tree listing (`find backend/src -type f` ≈ 75 files); `next.config.mjs:8–24` (rewrites `/api`, `/uploads`, `/socket.io` to backend `BACKEND_INTERNAL_URL || 127.0.0.1:5000`); frontend pages inventory (`login/page.js` ≈1792 ln, `dashboard/record/page.js` 4414, `dashboard/classes/[id]/live/page.js` 4173, `dashboard/messages/page.js` 3178, `dashboard/quizzes/page.js` 2527 lines).

**(c) Consequences.** One process owns HTTP + WebSocket + scheduler + backup: operational simplicity (one unit to deploy, one log stream) at the price of a **scaling ceiling** (§13). Domain boundaries are *naming* boundaries only: the modules share table fan-out patterns and several cross-module edges (AI→school/sida, AI→quizzes; school/finance/attendance→SMS gateway in-memory). That is acceptable for one team until N>1 schools share the install (§5).

**(d) Classification.** Monolith with codified domains: **appropriate debt** for a small team. Two *architectural defects in waiting*: (i) frontend pages past 2,500 lines are effectively unbound contexts inside a route file; (ii) socket + cache + scheduler state live only in process memory, which silently rules out horizontal scale (§13).

**(e) Improvement.** Leave the monolith; enforce two cheap conventions in code review/PR template: route files stay ≤~600 lines or their logic moves to a service module (already true for `assignments/quizzes/attendance/messages/notifications/ai` — extend the pattern to `gradebook`(682), `videos`(773), `school`(729), `finance`(530)); and define "one vertical slice per module folder" as the boundary rule. **Effort: S (<1 wk, no deps, docs + review checklist).**

## 2. Backend Architecture & Module Dependencies

**(a) Implementation.** Layered request pipeline in one `app.js` (529 ln): dotenv → NODE_ENV hard-exit → server+socket init → compression → helmet → cors → morgan → body parsers (10 MB) → `persianNormalizer` → authenticated `/uploads` static → global rate-limit (600/15 min, IP) → auth rate-limit (30/15 min on 4 POSTs) → health/system endpoints → two inline global routers → 23 module routers → 404 → errorHandler → listen + in-process scheduler (WAL checkpoint/perf backup every 5 min, WAL checkpoint on SIGTERM). Modules follow routes→controller→service except `gradebook`, `videos`, `school`, `finance`, `courses`, `feedback`, `schedules`, `discipline`, `tickets`, `analytics` — route-only, fat handlers querying `db` directly (+ auth asserts + audit where relevant).

**(b) Evidence.** Pipeline table (`app.js:55–121,123–152,195–303,306–451,470–521`); router list and per-module guards (`app.js:445–467`); layered DAG from `require` heads across all modules — zero import cycles; notable edges: `paperToDigital.service.js:21,22`→`sida.service`/`quiz.service`; `finance.routes.js:214–216`→validators/dbHelpers/smsGateway; `class.controller.js:226,244`→lazy `externalLive.service`; `app.js`→`socket.js`→`classroomPersistence.js`; dead `services/sms.service.js` (89 ln) required by no one; undeclared installed deps (`better-sqlite3@13.0.3` drives `knexfile.js:12` but is absent from `backend/package.json`; `@google/genai` in root manifest only, lazy-required at `ai.service.js:103`, `paperToDigital.service.js:27`).

**(c) Consequences.** The DAG shape is genuinely healthy (no cycles). The fat-handler split is the main defect: business logic, guards, and DB access coexist per-endpoint inside 600–800-line route files (`finance`, `videos`, `school`), so the security rules of the house live in scattered imperative code; the only structural guardrail is the regex-based **ratcheting lint** (`backend/scripts/lint-unscoped-queries.js`, 289 ln) with baseline of exactly **1** known unscoped-lookup exception (`courses/:id/enroll`). That's a very low bar that CI actually enforces — culturally good, structurally weak (it only greps `db('…').where({id: req.params.x})` in route files, and its header even names a helper, `assertPaymentScope`, that **does not exist** in `middleware/auth.js`).

**(d) Defect vs debt.** (i) Coherent route-only fat handlers instead of services: **debt** (fixable by convention + incremental moves, no redesign). (ii) `assertPaymentScope` phantom doc + a lint ratchet that only sees one syntactic shape: **defect-in-tooling** — it *claims* a boundary that isn't implemented. (iii) Undeclared `better-sqlite3`: **deployment defect** (npm ci/audit can't resolve; CI and Docker builds can't reproduce the graph reliably — see §3/§11; affects 02, note ENOLOCK). 

**(e) Improvement.** (1) Move guards/queries for the 8 fat modules into adjacent `*.service.js` files (pattern already exists); do it module-by-module behind green tests — each move is independent. (2) Delete `sms.service.js`; declare `better-sqlite3` in backend manifest and `@google/genai` (or vendor behind an internal `ai/kv` provider interface, §9). (3) Extend the ratchet: pattern for `db('x').where('id', req.params)` (string form) + service-layer coverage + generate the baseline entry list in CI comment. **Effort: S per module (list in roadmap Ph1); ratchet extension S.**

## 3. Frontend Architecture & State Management

**(a) Implementation.** Next 15 + React 19 + Tailwind 4, all pages `'use client'`, so App Router provides routing/SSR-shell only while pages hold the weight. State = a single zustand family: `stores/authStore.js` (~88 kB, 46 states) owns identity + tokens with **localStorage persistence** (`accessToken`, `refreshToken`, `user_profile`, `locale` at `authStore.js:88–116`), plus thin per-domain stores (`classStore.js` ~146 ln) and per-page `useState`. Network: hand-rolled axios instance `lib/api.js` (~207 ln) with per-request baseURL rewrite, an allow-list origin gate (`api.js:29+`), Bearer attach, 401→`/auth/refresh`→retry, final hard redirect to `/login/`. Socket: lazy singleton `lib/socket.js` (42 ln), token auth callback, `withCredentials: true`, 15 reconnection attempts, consumed by 10+ pages. No Next middleware (`frontend/middleware.*` absent) → **no server-side route protection at all**; the layout redirects client-side.

**(b) Evidence.** `frontend/package.json`; `next.config.mjs`; store/lib sources above; 44/50 client marker census (inventory); `AutoUpdateChecker.js` 236 ln (build-hash compare, OTA); `CallModal.js` 319 (getUserMedia loop, no real WebRTC); `test_all_panels.js` (19 kB root, plain-http CLI driving a live backend across 4 roles' panels); no frontend test files anywhere in `src/`; no TS (`jsconfig.json` maps only `@/*`); i18n: none — Persian strings hardcoded inline; numeral/date helpers are local wrappers.

**(c) Consequences.** SPA-model benefits (offline-tolerant rewrites, Capacitor reuse) without App Router benefits (SSR caching, server components). Giant pages (`record` 4414, `live` 4173) mean every edit recompiles a route the size of a library, review is diff-hostile, and knowledge silos form around each page. localStorage tokens ⇒ XSS reads both secrets (§6/SEC-CORS-001 context); client-side gating means crawlers/anyone with JS disabled hit unguarded routes. `out/` static + proxy rewrites ⇒ the "backend" CORS posture never binds to the real origin in dev, hiding integration bugs.

**(d) Defect vs debt.** Single-client-shell SPA: **debt by choice**, valid for the Capacitor target. Five 2,500–4,400-line pages, zero frontend tests, no middleware gating, token persistence in localStorage: **architectural defects** (security + maintainability floor), each independently fixable.

**(e) Improvement.** Phase-gated, no rewrites: (1) split the four largest pages along existing comment-blocks into `components/<feature>/…` import-only refactor (no behavior change); (2) raise `next middleware` to gate `/dashboard/*` (5-line edge guard that redirects unauthenticated to `/login/` — kills the client-only gate class); (3) move tokens to **httpOnly `SameSite=Strict` cookie** (paired with backend CORS fix, §6) — one PR spanning `api.js` interceptor + login/logout/refresh; (4) add a `vitest` smoke over `authStore` + `api.js` interceptors (the two pieces every other page depends on — highest-leverage frontend tests possible at this size). **Effort: S/M; deps: backend cookie-migration PR; zero infra.**

## 4. Database Schema & Data Relationships

**(a) Implementation.** better-sqlite3 through knex; 17 idempotent migrations (`hasTable/hasColumn` guards), pragmas at pool (`knexfile.js:18–29`: WAL(2), `synchronous=NORMAL`, `busy_timeout=10s`, `cache_size=-64000`, `foreign_keys=ON`). ERD core: `schools`→`classes`→{assignments, quizzes, announcements, videos, weekly_schedules, gradebook_categories}; `class_members` unique(class,user); `parent_student_links` unique(parent,student); `tuition_ledgers` unique(student, academic_year) ← `tuition_installments`; `users` global composite uniques replaced in migration 016 to `(school_id,email)/(school_id,phone)`; post-016 extras: `username` unique (per global collision caveat — §5), `revoked_tokens`, `audit_logs` (**no school_id** — joined at read via `auditLogger.js:57–79`), `live_classroom_sessions`, `system_settings` KV, `teacher_document/documents/study_notes`, `gradebook_shared_reports`.

**(b) Evidence.** Migration catalog (`001…017`, idempotent guards throughout; `016` drops old global uniques → composite; `012` adds `users.school_id` — a *retrofit*); seeds (`001_school_data.js` 514 ln, `002`, `003`); **only `users.school_id` and `classes.school_id` exist** — every message/announcement/gradebook/finance/ticket/courses/attendance table is a *global* table without a school column; typo-in-data-flag: seed writes tuition year `'1403-1404'` in **Latin** digits while migration 006 column default is Persian `'۱۴۰۳-۱۴۰۴'` (`003` vs `006:112`) — real operations-bug-shaped inconsistency; school deletion onboards orphans: class/school FKs are `SET NULL` (`001`), so deleting a school orphans every second-tier table.

**(c) Consequences.** Tenancy is a **query-writing convention**, so every new read must remember to join `classes`/`class_members` — the ratchet lint only pattern-matches a fraction of that responsibility. No systemic cross-tenant *accident* is guaranteed; correctness depends on author diligence per route (see AR-04 in the security register). Persian-digit date strings (`due_date`, `paid_at`) break ISO ordering/DATE functions and already disagree across sources. `User-visible` global uniques (`join_code`, `username`, ticket/tracking/course codes) force future cross-school code coordination. Cascade-less delete semantics (SET NULL) produce half-orphaned data.

**(d) Defect vs debt.** (i) school-scoping-by-convention + no cross-tenant regression test for reads: **defect** for a system whose metadata (`metadata.json`) advertises multi-tenant SaaS. (ii) Persian date strings + Latin/Persian digit inconsistencies: **debt→defect boundary** (long-term reporting/ordering bugs already seeded). (iii) Single SQLite file: **debt** as chosen infra (§13).

**(e) Improvement (schema-side, smallest viable).** (1) Migration 018: add nullable `school_id` to the first-tier entity tables (messages, announcements, gradebook_*, tuition_*, message_groups, school_tickets, attendance_*, feedback, call_sessions, notifications, courses) + composite indexes `(school_id,x)`; backfill via class-membership join; route scoping then becomes *index-able and lint-checkable*; (2) normalize financial dates to ISO-8601, expose Persian presentation at the API edge only; (3) DB-level school *delete* is out of scope — keep soft-delete/deactivation via `is_active` (already on users). **Effort: M (2–4 wks incl. backfill + isolation tests); deps: migration tooling + two-school fixture tests. No infra change.**

## 5. Multi-Tenant Architecture

**(a) Implementation.** "Convention + application-layer scoping": `users.school_id` + `classes.school_id`; tenant ID carried by JWT payload (`userId, role, tv`) + resolved per request; ownership asserts `assertSameSchool` (auth.js:52–64), `assertOwnsClass` (74–129 with `allowEnrolled`), `assertOwnsResource` (134–148), `assertTeacherOfStudent` (153–160 — same-school **only**, no teaching-link check). The financial/analytics modules scope by joins via ledger→student→school. `analytics.routes.js:13–32` uses explicit strict school scoping — the most rigorous example in the codebase.

**(b) Evidence.** §4 facts (two school_id columns of ≈40 tables); security-phase tests encode partial protections (`[A23]` backups role-gate at `extended-findings.test.js:77–88` — status-only); SEC-DATA-001**: backup/download artifacts are role-gated without school scoping (`app.js:240–279`, yo dbMaintenance whole-file copy); SEC-AUTH-001: cross-tenant student lookup by code (`auth.service.js:477–483`); per-school data isolation + cross-school access regression tests exist only for a handful of modules (see 03_UNRELIABLE_TESTS.md coverage gaps).

**(c) Consequences.** With metadata expecting registered multi-school SaaS, the current design is **one-tenant-per-install in truth**. Every growth event (second school on the same deploy, or one school scaling to >a few ~100 concurrent users) forces: reconciliation of global code spaces (`join_code`, `username`, `ticket_number`…), per-query discipline everywhere (unbounded — the lint ratchets one pattern), and a single-writer SQLite bottleneck (§13). Cross-tenant leakage classes already observed in audit (backups, student lookup, directory) show the convention is *failing at the seams today*.

**(d) Defect vs debt.** Missing structural school scoping while selling multi-tenancy: **architectural defect** — it is the root of at least three Critical-severity-adjacent security findings (SEC-DATA-001, SEC-AUTH-001 cross-tenant oracle, AR-01/04 register). Rate-limit gaps and role lists are independent **smaller defects**. Everything else (per-query style, assert library, ratchet CI step) is good HLD debt.

**(e) Improvement.** The 018 migration+scoping suite from §4 is the *structural* fix at SQLite scale; add a **cross-tenant regression matrix fixture** (two schools × each module × must-deny-set) in the backend test harness — the harness already provisions two schools (`fixtures/twoSchools.js`, school-a/school-b), so this is mostly new test files, not new infra; expand the ratchet lint to service files and to `whereRaw` school-free selects of first-tier tables. **Effort: M; deps: §4 migration + modest test authoring; no infra change, explicitly no service-per-school at this stage.**

## 6. Authentication & Authorization Design

**(a) Implementation.** Stateless two-token JWT pair: access (`JWT_EXPIRES_IN||15m`, claims `{userId, role, typ, tv, jti}`) + refresh (`JWT_REFRESH_EXPIRES_IN||7d`, separate secret); JTI blocklist table `revoked_tokens` (type `refresh`, `expires_at`), single-use refresh rotation bumping `users.token_version`, `token_version` session-wide revocation; `authenticate` (`auth.js:166–242`) accepts **Bearer or `accessToken` cookie**, rejects `typ=refresh` as access, checks active row + version + blocklist; role model = flat string on `users` with hard-coded vocabulary (`SELF_SERVICE_ROLES` vs `PRIVILEGED_ROLES`, server-side collapse to `student` in `resolveSelfServiceRole` auth.service.js:45–53, so privileged roles aren't client-assignable); `authorize(...roles)` role-aliasing expansions; `requireClassMember` per child-router for class-scoped mounts (`mergeParams:true`, express-4 child flattening); logout/revoke-clear cookie.

**(b) Evidence.** `auth.js` line map (§8 of backend inventory: helpers at 5,11,52,74,134,153,166,248,286,311); token lifecycle at auth.service.js:577–668,1157–1175; controller flows 270–347; `tests/` ratchets the whole chain (`[A3]`, `[A21]`, `[Arch-P1-*]` all green in 145/145 run).

**(c) Consequences.** This is the strongest subsystem in the codebase — session revocation, rotation-replay guard, class ownership with enrolled-parent participation. Residual flaws: (i) **cookie-token dual path + open CORS + no CSRF tokens = credentialed CSRF/origin theft** (SEC-CORS-001, `app.js:92–98` + `auth.js:11–29`); (ii) `assertTeacherOfStudent` never proves the "teacher actually teaches this student" relation — a school_admin/counselor of same school passes as teacher-of-student, which the product model permits (adviser sees advisee finances) — ambiguous at API layer; (iii) flat string roles with hard-coded vocab scattered across services (admin-roles list in **two** places: `auth.js:5 ADMIN_ROLES` + expansions in `authorize` 261–268); adding a role = grep-and-hope.

**(d) Defect vs debt.** (i) **defect** (security, immediately reachable); (ii) **specification debt** — decide and document; (iii) small-drift debt — fix with one shared capability map.

**(e) Improvement.** (1) CORS: explicit FRONTEND_URL allowlist + remove cookie-as-refresh path in favor of **httpOnly SameSite=Strict cookie for auth + CSRF double-submit on mutating endpoints** (or Bearer-only; pick one). (2) Extract role vocabulary into a single `capabilities.js` map (role → permitted actions) that `authorize()` + `assertTeacherOfStudent` consult — kills the two-list drift. (3) Add `/auth/parent-login` to authLimiter + same-body 401s (SEC-AUTH-001 low-hanging). **Effort: S–M each; deps: none beyond current mocks; cookie move pairs with §3(3).**

## 7. Financial Ledger & Transaction Design

**(a) Implementation.** Implicit-liability ledger: `tuition_ledgers{student_id (unique per academic year), balance, paid_amount, status('settled'|'partial')}` + `tuition_installments{ledger_id, amount, status('pending'|'submitted'|'verified'), due_date( fa-IR string), paid_at, tracking_number, authority, bank_name, verified_by}`; routes: ledger read (role-gated block: student only-self, parent via links/student_code, staff via `assertTeacherOfStudent`), `pay-installment` (submission only, `status:'submitted'`, tracking `-`/bank name), `verify-installment` (admin/manager/financial_officer/accountant, manual confirmation → recompute ledger), `initiate-payment` (offline `authority` prefixed `A000…`), `callback-verify` (client-stated `status:'OK'` **trusts body**, marks verified, recomputes ledger, logs `SHAPARAK_ONLINE_SETTLEMENT` audit + fake receipt SMS), local `validate-sheba` ISO-7064 Mod-97-10 with bank-name table.

**(b) Evidence.** `finance.routes.js:19–212, 222–238, 240–404, 410–527` read in full; no knex transaction wrapper anywhere in the settle path (independent awaits at `:138–155`, `:184–208`, `:456–523`); idempotency only rejects re-verify of same installment (`:177–182`, `:445–450`); `smsGateway.js:21–56` records dispatch entries in an **in-memory ring buffer (500)** with `status: 'delivered_service_line'` — i.e. the system *claims delivery* with no provider; `pay-installment` receipt uploads accept any URL; `due_date` Persian string from seeds/static data, `paid_at` from `toLocaleDateString('fa-IR')` at write time.

**(c) Consequences.** Settlement = pure DB write + notice → **SEC-FIN-001** (Critical 9.2): any authenticated non-counselor — incl. the student themself — can self-settle, zero the balance, and plausible-deniability follows via broadcast SMS. Partial-failure mode: process crash between the installment update and ledger recompute leaves money state inconsistent (no transaction, no outbox, no compensation). Accounting conventions absent: no double-entry/audit ledger semantics, no reversal flow, no currency-as-minor-unit normalization (Rial ints are fine, but strings are not), no statement/status machine beyond 3 statuses, Persian date strings preclude native ordering/compliance queries.

**(d) Defect vs debt.** Trusting the client's `status:'OK'` and bypassing PSP verification: **defect** — the money path cannot be designated "architectural" anything but broken. Missing transactionality around multi-write settles: **defect** (recoverable crash states). Manual `verify-installment` + receipt-file path: **ordinary product debt.** Persian date strings, ring-buffer SMS, `A000` authority convention: **debt** (interfaces that must be specified before integration vendors).

**(e) Improvement (integrity-first, smallest).** Wrap every mutating settle path (`verify-installment`, `callback-verify`) in a **knex transaction** + guard `SELECT … FOR UPDATE`-style serialized installment state machine transition assertions (`pending|submitted` → `verifying` timestamp → `verified`, reject otherwise); add `EXTERNAL_REF` uniqueness (`authority` unique index) for idempotent PSP callbacks; schema ISO dates for `due_date/paid_at` (keep fa display at edge); replace ring-buffer SMS with a **provider adapter interface** (`sms.provider.js`) with the buffer kept only as dry-run/Dev fallback — and make `dispatched` an honest tri-state (`queued|sent|failed`) only where real delivery is observed. **Effort: S for transactions+idempotency (3–5 d), M for PSP verify integration (needs vendor contract, 2–4 wks, security Phase-0 aligned); deps: none new.**

## 8. Real-Time Communication Architecture

**(a) Implementation.** In-process Socket.IO 4 server on the same http.Server as Express; JWT handshake auth (token in `auth.token`/`Authorization`/`access_token` cookie incl. blocklist+version checks, else disconnect); per-class rooms `class:<classId>` with server-side participant state (`io.of('/').adapter.rooms` plus explicit `activeClassrooms` map: participants, drawn strokes cap 2000, chat cap 100, whiteboard/doc state); full live-class event catalogue (join/leave, live start/end, whiteboard ops/draw/undo/sync, doc changes, permissions (student/hand/mic), screen-share, audio chunks, chat, WebRTC signaling); teacher verbs gated by room role; whiteboard/chat debounced-persisted to `live_classroom_sessions` (`classroomPersistence.js`, 1.5 s upsert).

**(b) Evidence.** `socket.js` read in full: CORS `callback(null,true)` **any origin + credentials** (89–102); handshake auth 104–151; join ACL at 169 incl. `assertOwnsClass(..., {allowEnrolled:true})`; channel `maxHttpBufferSize: 5MB` (91); event table incl. **unguarded** relays: `screen_frame` (563), `live_video_frame` (678) check only classId equality; `webrtc_signal` (662–670) forwards to an arbitrary `targetSocketId` **without room membership validation** (a connected socket anywhere on the fleet can be signaled); authz denials emit nothing — bare `return` except join's `error_message` (171); rate limits: none per-user per-emitter (all socket events outside HTTP limiter).

**(c) Consequences.** Functionally a well-built classroom backend: reconnection-safe by design (room state server-side), durable whiteboard/chat, teacher verbs truly server-enforced. Architectural consequences of the current shape: (i) any-origin CORS + cookie-token handshake repeats the SEC-CORS-001 exposure on the socket surface; (ii) `webrtc_signal` global addressing is a **design defect** — clients can signal any other connected client (leakage of SDP/ICE, side-channel); (iii) silent denials make clients unblockable UX bugs look like "no signal"; (iv) heavyweight frame relays are server-CPU/memory-bound (5M buffer cap), fine per-class, painful at fleet scale — and the in-memory adapter means **no multi-instance** (`config.redis` exists but no client/adapter).

**(d) Defect vs debt.** (i)+(ii) **defects** (reachable, small fixes). (iii) UX/ops debt. (iv) capacity envelope documented but unbuilt-out: debt-with-a-trigger (§13).

**(e) Improvement.** Room-validate `webrtc_signal` targets (forward only to sockets whose rooms include currentClassId); emit a standard `authz_error{event,reason}` on denial so clients fail visibly; unify CORS policy with §6(1); add per-connection/token revalidation hook on teacher verbs (cheap authoritative check already exists per-join, add per-event for `toggle_hand_raise`-analoga later only if abused); keep single-node + document the ceiling (why: current room caps + per-class participant counts make single-instance viable for target school sizes; revisit only with observed concurrent-class data). **Effort: S each; deps: none.**

## 9. AI Integration & Data Integrity

**(a) Implementation.** Dual-engine by design, single engine in practice. `paperToDigital.service.js` (601 ln): cloud path = `@google/genai` `gemini-3.8-flash` w/ `responseSchema` (dynamic require, guarded `try/require` at :24–30; prompt = scanned OCR text verbatim, 115–123) — **package not installed in this tree**; deterministic fallback = regex line-splitter for roster/gradesheet/exam with *hard-coded confidences* and — when OCR text is empty — **hard-coded fabricated rows** with Persian names/national codes (195–225 roster, 265–289 grades, 335–357 exam). Commit endpoint accepts any client items (`ai.routes.js:45–56` + `:47` passthrough), `needs_review` computed in `postProcessExtractedItems` (392–456) *never enforced* at commit; roster commits pump through `sidaService.importRoster` (school_scoped-gated only) with identity overwrite of existing students; exams commit straight into `quizService.create`. `ai.service.js` (content generation): Gemini call w/ template prompt + unvalidated `JSON.parse`-style pass-through (raw LLM text returned, 102–123), otherwise deterministic template fallback for quiz/announcement/homework.

**(b) Evidence.** Full read of `paperToDigital.service.js` + `ai.service.js`; dynamic harness records from 2026-11-10 suite & re-run: C1/C2/C3 (empty-OCR fabricated rows; gradebook 18→3.0 incl. `needs_review:true`; fabricated pupils+parents inserted), reproduce 2026-11-11 **10/10** pass. See security deliverables for SEC-AI-001/002, FW-AI-002/003.

**(c) Consequences.** The "human-in-the-loop commit pipeline" is data labels without enforcement: an authorized teacher ⇒ arbitrary database mutation of the official records with no provenance, no review trail, no audit log. If the Gemini path is ever enabled, scanned-input prompt injection applies *directly to official data* (indirect prompt injection), plus uploads of scanned PII to a third party with no visible processing agreement. The deterministic fallback's fabricated rows are a data-integrity defect *in the current* tree — live today without any Gemini dependency.

**(d) Defect vs debt.** (i) Commit trusts client entirely + needs_review unenforced + empty-OCR fabrication: **defect**. (ii) Confidence/review labels that compute nothing real (0.93/0.79 constants, feasibility text as marketing): **debt/feature-fiction** (it *claims* honesty it can't measure). (iii) Engine absence vs `metadata.json` capability advertising Gemini: **latent defect** (integrating as-is imports prompt-injection + PII-leak paths). ## 10. File Storage & Upload Architecture

**(a) Implementation.** Upload: multer 1.4.5-lts disk storage, UUID filenames (`middleware/upload.js:47–67`; fileFilter extension/Mime gate 72–105), limits `{fileSize: MAX_FILE_SIZE||50MB, files: 30}` (:110–114), `upload.any()` at `upload.routes.js:106` ⇒ **≈1.5 GB ceiling per POST request**; optional sharp pipeline (auto-rotate/downscale to 1920² q82 + thumbnails; silent no-op path if CPU lacks SSSE3 or sharp fails :1–26, 96–99). Serving: `app.use('/uploads', authenticate, express.static(uploadDir))` with nosniff + blanket `default-src 'none'; sandbox` CSP on all responses and text/plain-for-html/svg (:109–121). Video module (`videos.routes.js` 773) expands folders/metadata/thumbnails/streaming + AI manifest generation over stored media. Filesystem only: **no DB table indexes files** — existence/metadata lives in `videos` table partially + static listing, `uploads/` is otherwise unlisted.

**(b) Evidence.** This + `01` security register: SEC-UPLOAD-001 (multer DoS advisories on same path); FW-UPLOAD-002 stale listing; test artifact: `uploads.test.js` writes fixture file into committed `backend/uploads/` at :29–30 (`VIDEO_UPLOAD_DIR = path.join(BACKEND_DIR,'uploads')` :19) — the *static serving layer itself depends on a committed directory*; `.gitignore`: `backend/uploads/*` (gitkeep kept).

**(c) Consequences.** Per-request 1.5 GB ceiling + no disk-usage guards ⇒ single authenticated user can fill the volume (memory pressure amplified by multer advisory classes — SEC-DEP-001's 11 HIGH advisories target exactly this path); hashless filenames ⇒ no dedupe/integrity checks; no manifest ⇒ orphans can't be swept (stale re-upload serving); `video` rows reference `file_url` strings without FK to a file table, so rename/broken symlink errors surface as dead media; authenticated static siting means *any* upload (incl. future exploits) is downloadable by any authenticated user who guesses/needs the name.

**(d) Defect vs debt.** Missing request-level size/disk guards: **defect**. No file manifest table: **debt** (grows hostile with any cleanup feature). Thumbnail/folder system (videos): functional debt, fine at current scale.

**(e) Improvement.** Add a request gate middleware: `Content-Length`/multer `fileSize`×`files` sanity (e.g. 200 MB/post configurable), per-school disk watermark check via `server-side quota row` (school_settings KV already exists — `system_settings`); create a minimal `stored_files{file_name, bytes, mimetype, owner_school_id, created_by, etag}` written on upload-commit + sweep orphans on schedule (the scheduler already runs in-process daily); enforce dedupe via content hash before write. **Effort: S (gate+quota 2–3d), M (manifest+sweep 1–2 wks); deps: none.**

## 11. Deployment & Infrastructure

**(a) Implementation.** Three realized or dispatched paths, all single-node: (1) `docker-compose.yml` (20 ln): one backend service, `build: .` (backend Dockerfile node:20-bookworm-slim, `npm ci --omit=dev`, non-root, `CMD node src/app.js`, NODE_ENV=production — **never runs migrations**), bind-mounts `./educonnect.db` and `./uploads` as files/dirs; restart: unless-stopped, no healthcheck; (2) `Deploy-Windows-Server.ps1` (111 ln): manual Node 20.18/Git install → clone → **`npm ci --omit=dev` with no committed npm lockfile** → writes `.env` (PORT=3000 backend) → `npx knex migrate:latest` (via .env production env → sqlite file) → PM2 + cloudflared tunnel exposing `localhost:3000`; (3) dev: `dev-server.js` spawns backend+frontend; tunnel keeper + `auto_sync.js` (git-fetches every 15 s, and on divergence **`git reset --hard origin/main`** in a dedicated clone, writes `backend/sync_status.json`).

**(b) Evidence.** Listed files; `backend/Dockerfile`; `backend/scripts/{tunnel_keeper,start_permanent_tunnel.*}`; **`backend/educonnect.db` currently 4 KB (empty file) with WAL sidecars** — the migration-never-ran state is literally the current dev state (`docker compose up` on this tree ⇒ empty DB, all data routes 404/empty); compose mounts `./educonnect.db:/app/educonnect.db` but not the `-wal/-shm` sidecars → those live in the container's ephemeral layer ⇒ **potential checkpoint-window/snapshot corruption on restart**; `auto_sync.js:21-39` (reset --hard loop).

**(c) Consequences.** The compose file *looks* reproducible but isn't: no migration step, no frontend, no named volume incl. sidecars, port 5000 raw. Windows deployment relies on `npm ci` without lockfile — **ENOLOCK failure by construction** (npm needs `package-lock.json`; only `bun.lock` exists, unreadable to npm) unless someone commits node_modules (not in tree) or runs `bun install` — and the pipeline pins Node 20.18/Git 2.47. `auto_sync`'s hard-reset pattern trades operator control for update velocity: no rollback discipline, plus the deployment's tracked-remote is mutable origin/main. PM2+cloudflared = manual lifecycle (no rollout, no restart-of-backend on auto_sync divergence — presumably tunnel wraps proxy, the reset clone ≠ running tree… the mechanism as documented conflates two trees; unverified operational half).

**(d) Defect vs debt.** Missing migration-in-image + sidecar volume + no healthcheck: **defect-fleet** (fresh deployments are broken, and crash-recovery may corrupt). no lockfile-visible-to-npm in Docker/ps1: **deployment defect** (EC: reproducibility grade 03-dependent). PM2/tunnel/auto_reset combination: **operational debt** with one sharp edge (hard-reset).

**(e) Improvement (concrete sequence, cheap each).** (1) `docker-compose`: add an `init` one-shot service (`docker run backend npm run migrate` via shared `entrypoint` + `command` override with proper env) that finishes before backend starts (compose `depends_on: condition: service_completed_successfully`); mount **named volumes** covering `educonnect.db`, `-wal`, `-shm` as one dir (mount the parent) or run a single host postgres file layout… simplest: mount `./data:/app/data` and point `DB_PATH` there; healthcheck `wget /api/health`; (2) commit a real `package-lock.json` (or switch Dockerfile/ps1 to `bun install --frozen-lockfile` — pick ONE package manager, document, delete the other story); (3) ps1: refresh Node/Git pins, replace hard pm2 resurrect with `appointments` service + ensure migrations at install; (4) replace auto-reset with a **watch-and-restart + announce-readiness** model (tag-based) — keep git-sync only with a `HEALTHCHECK`-driven reload, never `reset --hard` a running tree. **Effort: S/M each; deps: none.**

## 13. Performance & Scalability

**(a) Implementation.** Single Node process; SQLite WAL (2), `busy_timeout=10s`, single writer; in-memory LRU cache (60 s) tokens/school-keyed; compression (1 KB+); body 10 MB; global HTTP throttle 600/15 min; no pagination discipline anywhere in the audit (route-level `.first()`, full lists for tuition/message/sessions — presentation-level paging at best); video/audio frame over sockets (5 MB buffer cap); whiteboard/chat in-memory & debounce-persisted.

**(b) Evidence.** config/pragmas above; route census (service-level lists); `socket.js:91` buffer cap; no OFFSET/limit found in finance ledger/messages/announcement routes (all-return patterns); 145-test suite executes in ~4.2 s on this commodity host with full boot per file — a healthy fixture signal for sizes tested; row-table sizes in seeds are demo-scale.

**(c) Consequences.** Capacity envelope: one process, one SQLite writer → **writes serialize globally**, WAL checkpoint pauses (fine at ≤~10^3 writes/sec-class, harsh at fleet SMS/multi-chat scale); reads multi-plex*/fine; room/frames: per-class CPU-bound relays — expect GPU-less single-digit concurrent live classes of any size before CPU levers out; `.first()`/list-all patterns are fine at current scale but are the first thing to break when tenant data compounds (each school multiplies rows).

**(d) Defect vs debt.** Single-writer ceiling baked in without a documented trigger/envelope: **debt-with-trigger** (knexfile pg path already scaffold-ready: `DB_CLIENT=pg` — unused). Missing pagination/lazy fields at API edge: **debt→defect** only when multi-school data compound; add `limit/offset` contract now while fields are cheap. Frame-relay P95: **capacity debt**, the websocket relay already the costliest continuous unit.

**(e) Improvement.** (1) Pagination/limit contract on the 3 accumulating list APIs (finance ledger installments are per-student — bounded; messages/directory/announcements — paginate + `createdBefore`; socket chat already capped 100); (2) `count`-free semantic reads: pre-aggregated `analytics` endpoints (analytics module exists — expand, it already scopes correctly); (3) document envelope: expected reads/writes per school, plus load-test stub (`artillery`/`k6` one-file plan) checked into repo, ran in CI once/monthly — cheap and catches the single-writer cliff early; (4) *ANY* horizontal step (pg + redis-adapter + queues) only behind env-flagged config — resist until measured. **Effort: S each; deps: none into roadmap; marker addressed in §05.**

## Cross-cutting verdict

The system is a **well-cued layered monolith sized for one school's production deployment** and no more; its core disciplines (auth session lifecycle, test harness philosophy, ratchet-in-CI idea) exceed its means, while its three highest-egration seams are structural-at-the-edges: (1) the schema/tenant story, (2) the money path, (3) the "AI commit" trust model. Fix those in place, and the architecture holds for the roadmap horizon without new infra services.
